# v40 — 로그인 보안 작업은 성공했지만, 효율 우위는 확인하지 못했습니다

새 FastAPI 작업 하나에서 Codex와 Claude를 각각 BTH 경유/직접 실행으로 비교했습니다.
네 후보 모두 첫 구현 후 일반 테스트와 별도 행동 검사를 통과했습니다. 다만 Codex는
BTH 경유가 더 느리고 토큰도 많았고, Claude는 시간은 비슷하나 BTH 비용이 더 높았습니다.
**이번 결과는 구현 가능성을 보여주지만, 하네스를 쓰면 항상 유리하다는 증거는 아닙니다.**

## 무엇을 만들게 했나

공개 FastAPI Template의 `fastapi-04-constant-time-login` 작업입니다.

- 없는 이메일로 로그인해도 비밀번호 해시 확인을 수행한다.
- 비밀번호 찾기는 이메일 등록 여부와 관계없이 같은 응답을 돌려준다. 메일은 등록된
  사용자에게만 보낸다.
- 재설정 토큰에 대응하는 사용자가 없으면 잘못된 토큰으로 처리한다.
- 관련 회귀 테스트를 작성한다.

이름에 `constant-time`이 있어도, 이 검사는 요청 전체의 실행 시간이 일정하거나 모든
시간 기반 정보 노출이 사라졌음을 증명하지 않습니다. 해시 확인 호출과 API 동작을
검사합니다. 외부 메일·운영 DB·회사 코드는 사용하지 않았습니다.

기준 소스는 `7107f7e83acdf93272377ca97985dd3c51c47686`, 공개 수정본은
`689d7105e12039db84bb0e0c0cc797ca086192db`입니다. 요구사항·근거는 버전이 고정된
[코퍼스](../../benchmarks/public-backend-v1/corpus.json)에 있습니다.

## 같은 출발점을 준비했습니다

기존의 공개 FastAPI 검증 환경을 이 작업에도 선언했습니다. 일반 테스트는 준비된
기준 소스에서 **62개** 통과했고, 독립 행동 검사 9개는 기존 버그를 재현하고 공개
수정본에서 모두 통과했습니다. 별도 구현 모델에는 행동 검사 코드를 제공하지 않았습니다.

- 공통 환경 파일 6개: 실행 래퍼, 테스트 부트스트랩, 환경 계약 테스트, 합성 이메일
  도우미. 기존 파일 교체는 해시가 일치하는 이메일 도우미 하나뿐입니다.
- 실제 API 코드와 기존 API/pre-start 테스트는 공통 환경으로 교체하지 않았습니다.
- 기존에 캐시된 Python 의존성과 고정된 PostgreSQL 16 이미지만 사용했습니다.
  PostgreSQL은 이 공개 프로젝트의 테스트 의존성이지, 제품의 MySQL 우선순위 변경이 아닙니다.
- 사전 조사에서 임시 최소값 57로 실제 62개를 확인한 뒤, 모든 모델 호출 전에 최소값을
  62로 고정했습니다. 각 실행에서도 기준 검증을 다시 했습니다.
- 모델마다 각 경로에 같은 모델·`deep/high`·한 번의 호출·4분 호출 제한을 주었습니다.
  Codex는 BTH→직접, Claude는 직접→BTH 순서입니다. 후보를 수동 수정하거나 적용하지 않았습니다.

런타임은 `b188df307224ba2d91ba9da7ef058fea6d79811a`와 관련 파일 해시가 일치합니다.
이번 변경은 평가 환경·계약 테스트·증거입니다. 하네스 런타임 최적화를 한 결과로
잘못 읽으면 안 됩니다. 재현 명령은 [reproduce.md](artifacts/v40/reproduce.md)에 있습니다.

¹ 캐시 재사용 입력을 포함한 provider 보고 토큰입니다. 새로 처리한 입력이나 과금액과
같지 않습니다. Claude의 최종 usage에 보조 모델 토큰이 빠질 수 있으며 원본
`providerReported`를 보존했습니다. 비용 미제공은 0달러가 아닙니다.

시간은 일반 검증까지의 경로 시간입니다. 공통 설치·기준/수정본 사전 검사·후보의 별도
독립 검사까지 포함한 전체 대기 시간은 아닙니다. 모델 호출 시간만 보면 순서대로
225.721 / 150.270 / 83.871 / 94.719초입니다. 각 후보는 한 번의 실제 구현 호출이며
자동 재시도는 0회입니다.

이 표에서만 계산하면 Codex BTH는 직접 실행보다 **시간 1.50배, 토큰 1.66배**입니다.
Claude BTH는 시간 약 3.6% 감소, 토큰 약 1.3% 증가, 비용 약 23.3% 증가입니다.
각각 한 쌍이므로 일반적인 우열이나 원인으로 확대하지 않습니다. 네 실행은 독립 작업
네 개가 아니라, **같은 작업 하나에 대한 두 모델의 비교**입니다.

## 테스트만 세지 않고 변경 내용도 봤습니다

네 후보 모두 일반 검증 이후의 소스 지문과 현재 후보가 일치하고, 보호된 검증 입력이
유지됐습니다. 새 skip은 없었습니다. Codex 두 후보는 기존의 “없는 사용자이면 404”
테스트를 새 요구사항인 같은 응답/메일 미발송 테스트로 대체하고 재설정 검사를
추가했습니다. 이름 하나가 사라졌지만 실패를 감추기 위한 테스트 삭제로 보지 않았습니다.
Claude 후보들은 기존 테스트 이름을 모두 보존하고 검사를 추가했습니다.

등록 사용자·비활성 사용자 동작을 유지하면서 없는 사용자도 해시 확인을 수행했습니다.
`security.py`와 `test_user.py` 추가 변경은 정답 경로 목록 밖이지만, 공통 더미 해시와
인증 호출 검증이라는 이유가 있습니다. 평가기의 `unexpectedChangedPaths`는 정답
목록 외 경로라는 뜻이지, 곧바로 잘못된 변경이라는 뜻은 아닙니다.

반면 **Claude BTH 후보에는 사람이 검토할 품질 문제가 남았습니다.** 기존에 설정한
해시 객체를 재사용하지 않고 더미 해시용 설정을 다시 만들었습니다. 현재 동작은
통과하지만 나중에 설정이 따로 바뀔 수 있습니다. 또 주석·테스트 설명 중 시간 기반
사용자 추측을 방지한다고 넓게 주장하는 문장이 있습니다. 이번 검사는 그 보장을
증명하지 않습니다. `ruleViolations: []`는 관측한 실행 통제 위반이 없다는 뜻일 뿐,
설계·주석·모든 회사 규칙까지 훌륭하다는 판정이 아닙니다. 비교 후 후보를 고쳐서
원래 결과를 바꾸지는 않았습니다.

## 비용과 검색에서 찾은 개선 지점

BTH는 두 모델에 파일 후보 47개와 코드 발췌 약 10,119자를 준비했습니다. 요청 JSON은
약 30.6 KB이며, 그중 프로젝트 규칙/관례 영역 약 11.2 KB, 작업 영역 약 6.3 KB입니다.
중요한 로그인 라우트와 인증 구현 파일은 검색 순서 8·9번째였습니다. 이름 기반 정답
경로 기준 Recall@5는 1/3, Recall@20은 1, nDCG@20은 약 0.759입니다.

개선 후보는 명확합니다. **필수 규칙·출처를 유지하면서 관련 구현과 그 테스트를 먼저
보이고, 관련 없는 관례와 생성된 중복 설명을 줄여야 합니다.** 단, 요청 크기만으로
느려진 원인을 확정할 수 없습니다. 직접 실행도 파일을 읽었고 모델 실행에는 편차가
있습니다. 이 작업 이름/정답 파일에 맞춘 특례가 아니라 다른 작업에서도 검증해야 합니다.
이번은 명시적 deep/high 실행이며, auto/light 또는 가벼운 CRUD가 항상 이렇게 무겁다는
증거는 아닙니다.

Codex 직접 실행의 읽기 경로 기반 Recall@5는 1, nDCG@20은 약 0.712입니다.
**Claude 직접 실행은 읽기 이벤트 8개를 관측했지만 유효 읽기 경로가 기록되지 않아
영향 지표가 `null`입니다.** 이를 0점으로 처리하거나 결과 파일에서 역산하지 않았습니다.
경로 수집은 다음 수정 대상입니다. 현재 파일 경로 별칭 처리가 원인일 가능성은 있지만
원본 이벤트 경로가 저장되지 않아 이 실행의 원인으로 단정하지 않습니다.

## 이번 비교로 알 수 없는 것

- 두 경로 모두 모델의 build/test 실행을 제한하고 같은 평가기가 검증했습니다.
  **통제된 코드 편집 비교**이며, 평소 Codex/Claude가 스스로 테스트·복구까지 하는
  전체 사용 흐름과의 비교는 아직 없습니다.
- BTH 기록에는 Codex CLI `0.151.0`, Claude Code `2.1.239`가 남았습니다. 직접 경로는
  성공한 버전 탐색 결과 문자열을 보존하지 않아 별도 버전 증거가 없습니다.
- 모든 회사 규칙, 완전한 의미 기반 영향 그래프, 시간 기반 보안, DB migration,
  MySQL E2E, 실제 Windows, 두 개발자의 인수인계는 이 작업으로 증명하지 않았습니다.
- 일반 테스트를 통과한 후보라는 뜻이지, 배포나 회사 원본 적용을 승인한 것이 아닙니다.

## 검증과 목표 현황

환경 선언이 없을 때 새 계약 테스트가 실패하는 것을 먼저 확인했습니다. 수정 후
설정·환경·준비 테스트 20개, 비교 실행기·코퍼스·문서 등을 포함한 회귀 52개가 통과했습니다.
문법 검사와 최종 diff/문서 검사도 기록합니다. 종료 후 평가 전용 DB 컨테이너와
네트워크는 남지 않았습니다. 보존한 후보와 공유 캐시는 삭제하지 않았습니다.

원자료는 [Codex pair](artifacts/v40/codex-pair.json),
[Claude pair](artifacts/v40/claude-pair.json), [QA](artifacts/v40/qa.json),
[작업별 원장](artifacts/v40/corpus-ledger.json), [목표 현황](artifacts/v40/goal-status.json)입니다.
원장은 과거 프로토콜 결과를 별도로 표시합니다. 다른 시점의 실험을 합친 성공률이나
속도 점수로 읽으면 안 됩니다. **3개 백엔드·20개 작업과 전체 흐름 비교라는 목표는
아직 완료가 아닙니다.**

현재 원장에는 20개 중 과거 양쪽 실제 추론 기록이 있는 작업 9개, 그중 양쪽 모두
첫 시도 성공한 적이 있는 작업 4개가 있습니다. 행동 검사를 선언한 작업은 11개,
현재 검사 해시와 기준/수정본 실행 증거가 맞는 작업은 10개입니다. 이는 증거가 있는
작업 수이지 현재 버전의 성공률·성능 또는 전체 완성도 점수가 아닙니다.
