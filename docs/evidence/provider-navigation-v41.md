# v41 — 구현과 테스트를 같이 찾고, 초기 탐색 목록을 줄이기

v40의 실제 인증 작업에서 모델에 파일 47개를 전달했지만, 중요한 로그인 구현은
8번째였습니다. 이번에는 빠진 테스트↔구현 연결을 만들고, 초기 모델용 목록을
줄였습니다. 승인 계획·선언 규칙·DB 검토 신호·필수 검증은 줄이지 않았습니다.

## 고친 문제

규칙 분석기는 `backend/tests/api/routes/test_login.py`의 짝을 찾았지만,
탐색 그래프는 같은 폴더의 테스트만 연결할 수 있었습니다. 이제 같은 모듈 안의
병렬 `tests/...`와 `app/...`·`src/...`·모듈 루트 구조도 연결합니다. Python의
`test_name.py`/`name_test.py`, ECMAScript의 `.test`/`.spec` 이름을 지원합니다.

상대 디렉터리와 언어가 맞는 실제 구현 파일이 **하나일 때만** 연결합니다. 후보가
여럿이면 `ambiguousTestPaths`에 남기고 연결하지 않습니다. 다른 모듈의 이름만 같은
파일을 찾거나, 이 관계를 실제 테스트 커버리지로 취급하지 않습니다.

모델에게 처음 전달하는 코드 목록은 기존 문자 예산 안에서 fast 8개, balanced
16개, deep 24개까지입니다. 생략 수를 기록합니다. 이 목록은 시작 지점일 뿐이며,
모델은 승인된 범위 안에서 필요한 호출과 테스트를 추가로 읽을 수 있습니다.
편집 허용 범위와 실행할 테스트는 이 목록으로 정하지 않습니다.

기존에 프로젝트에 복사해 설치한 Pack이나 봉인된 그래프를 자동으로 덮어쓰지는
않습니다. 새 즉석 그래프는 새 indexer를 사용하며, 기존 Pack은 팀의 검토 후
업데이트·그래프 재생성이 필요합니다.

## 20개 공개 작업의 정적 비교

같은 고정 소스·요구사항·승인 계획에 대해 `7fb29f0`의 그래프/모델용 문맥과
새 그래프/문맥을 비교했습니다. 세 저장소의 작업 20개 모두 조사했습니다.
모델 호출, 프로젝트 테스트, 의존성 설치 없이 실행한 **탐색 비교**입니다.

| 모드 | 평균 Recall@5 전→후 | 평균 Recall@20 전→후 | 평균 nDCG@20 전→후 | 전달 문맥 바이트 감소 |
| --- | ---: | ---: | ---: | ---: |
| fast | 0.456 → 0.472 | 0.545 → 0.528 | 0.482 → 0.483 | 약 0.02% |
| balanced | 0.456 → 0.472 | 0.752 → 0.752 | 0.557 → 0.565 | 약 10.30% |
| deep | 0.456 → 0.472 | 0.752 → 0.752 | 0.557 → 0.565 | 약 17.88% |

여기서 문맥은 `codeContext`와 `projectConventions`의 직렬화 크기입니다. 승인된
task를 더한 크기도 원자료에 있지만, 전체 provider system prompt나 실제 토큰 수가
아닙니다. 정답 경로는 공개 수정본의 변경 파일 목록이므로 의미 기반 영향 분석의
완전한 정답이라고 볼 수 없습니다. 이미 알고 있는 코퍼스이지 미공개 검증셋도 아닙니다.

좋아지지 않은 사례를 남겼습니다.

- CORS와 자기 계정 삭제 작업은 관련 파일의 순서가 약간 나빠졌습니다. 테스트 쌍을
  함께 보여주면서 다른 관련 파일이 뒤로 밀릴 수 있습니다.
- fast 인증 작업은 Recall@5가 1/3→2/3으로 좋아졌지만, 작은 문자/파일 창 안에서
  `crud.py`가 빠져 Recall@20은 1→2/3으로 떨어졌습니다. fast에 의미 있는 문맥량
  절감도 없었습니다. 따라서 모든 모드의 검색 품질이 좋아졌다고 주장하지 않습니다.
- deep 인증 작업은 로그인 구현이 8번째→2번째가 되고 nDCG@20이 약
  0.759→0.907로 좋아졌습니다. 20개 안의 정답 경로는 모두 유지됐습니다.

정적 비교에는 실제 실행을 위한 테스트 환경 파일을 추가하지 않았습니다. 이 작업의
원본 그래프는 45개, v40의 준비된 실제 실행 그래프는 47개였던 차이도 이 때문입니다.
두 결과의 경로 수를 같은 환경으로 오인하면 안 됩니다.

## 안전 안내는 탐색 목록과 분리합니다

검토 중 또 하나의 회귀를 발견했습니다. custom 검증 명령을 쓰는 혼합 언어
프로젝트에서 Java 파일이 목록 상한 밖으로 나가면, 모델에게 보내던 Java 관계
변경 주의 안내가 사라질 수 있었습니다. 실제 변경 후 구조 검사와 필수 테스트는
이 목록과 무관하게 계속 실행되지만, 안내도 보존해야 합니다.

TypeScript 30개 뒤에 Java 파일이 있는 프로젝트와 custom 검증 명령으로 재현했습니다.
처음에는 안내 누락 때문에 테스트가 실패했고, 안내 선택에 축소 전 경로를 따로 전달한
뒤 통과했습니다. 실제 변경 후 Java 검사와 모든 필수 Gate는 바꾸지 않았습니다.

아래 실제 Python 비교를 먼저 끝내고 원본 결과를 기록한 다음 이 회귀를 고쳤습니다.
따라서 실제 호출 당시와 최종 코드의 `implementation-orchestrator.mjs` 해시는 다릅니다.
별도 요청 수준 회귀 테스트와 최종 전체 테스트로 보완했으며, 이것을 새 버전에서
모델을 다시 호출한 결과처럼 표시하지 않았습니다. QA 기록에 두 해시를 남깁니다.

## 실제 구현 비교와 최종 QA

고정 FastAPI 인증 작업을 새 출력 디렉터리에서 다시 실행했습니다. Codex
`gpt-5.6-sol`, deep/high, 경로당 한 번의 호출, 같은 4분 호출 제한입니다. 순서는
BTH→직접입니다. 일반 테스트 기준 62개, 독립 행동 검사 9개와 보호 입력은 양쪽에
같이 적용했습니다. 새 프로토콜은 `bounded-navigation-v41`입니다.

| 경로 | 일반 테스트 | 독립 검사 | 구현+일반 검증 | 보고된 총 토큰 | 재시도 |
| --- | ---: | ---: | ---: | ---: | ---: |
| BTH | 63/63 | 9/9 | 224.521초 | 516,506 | 0 |
| 직접 | 63/63 | 9/9 | 122.054초 | 231,600 | 0 |

둘 다 정의된 작업을 첫 시도에 완료했지만, **이번에도 BTH는 직접 실행보다 약
1.84배 느리고 토큰은 2.23배였습니다.** 토큰은 캐시 재사용을 포함합니다.
새 입력 토큰은 각각 52,701 / 48,236이며 비용은 둘 다 미제공입니다. 이를 0달러로
취급하지 않습니다. 표의 시간은 설치/대조군/독립 후보 검사 전체 시간이 아니며,
모델 호출 시간만은 각각 204.812 / 110.001초입니다.

BTH 요청은 v40의 30,642바이트에서 25,921바이트로 줄었고, 이번에도 선언 규칙
4개·지식 문서 7개·원래 승인 계획이 유지됐습니다. 초기 코드 목록은 47→24개입니다.
v40의 BTH 호출보다 시간·토큰이 적게 관측됐지만, 모델 편차·캐시·순서 효과를
분리하지 않았으므로 그 차이를 이 수정의 인과적 효과로 단정하지 않습니다.

BTH의 읽기 명령은 7회, 직접 실행은 3회가 관측됐습니다. BTH는 관련 정책·구조 문서와
검증 래퍼까지 확인했습니다. 목록 길이만이 아니라 필요한 정보를 어떻게 전달하고
중복 확인을 줄이는지도 더 검증해야 합니다. 이는 가능한 개선 지점이지 지연 원인을
확정한 분석은 아닙니다. BTH의 검색 지표가 더 좋아도 이번 완료 시간은 더 길었습니다.

후보의 실제 diff도 검토했습니다. 둘 다 없는 사용자의 해시 확인, 같은 복구 응답과
미등록 메일 미발송, 잘못된 토큰 응답을 구현했습니다. 기존 해시 도우미를 재사용하며,
시간 기반 정보 노출이 모두 사라졌다는 보장 문구는 추가하지 않았습니다. BTH는 기존
비밀번호 찾기 테스트 하나의 이름/기대를 새 요구사항에 맞게 바꿨고 직접 실행은 이름을
유지하면서 기대를 바꿨습니다. 단순 테스트 삭제나 skip 추가가 아닙니다. 둘 다 새
재설정 테스트와 해시 확인 호출 검사를 더했고, 보호 입력과 검증 후 소스 지문도 맞습니다.
후보를 수동 수정하거나 회사 원본에 적용하지 않았습니다.

이 비교는 양쪽 모두 모델의 build/test 실행을 금지하고 평가기가 검증하는 통제된
편집 비교입니다. 평소 CLI가 테스트·복구까지 스스로 수행하는 전체 흐름 비교가 아닙니다.
규칙 위반 0건도 관측한 통제 항목에 한정됩니다. 직접 실행의 CLI 버전 문자열은
아직 저장하지 않는 한계가 있으며, BTH 기록은 `codex-cli 0.151.0`입니다. 실제
Windows·MySQL 작업·두 개발자 인수인계·새 Claude 비교를 이번에 검증하지 않았습니다.

첫 실패 재현 4건은 수정 후 11개 테스트 모두 통과했고, 관련 회귀 94개도 통과했습니다.
Java 안내는 별도의 실패→통과를 확인했습니다. 최종 전체 테스트는 **596개 중 592개
통과, 실패 0개, 제외 4개**입니다. 커버리지는 라인 91.36%, 분기 82.95%, 함수 98.70%입니다.
이 수치는 기능 전체가 완성됐다는 점수가 아닙니다.
제외한 네 검사는 실제 MySQL, 실제 Maven/Gradle, Windows provider 실행,
Windows 자식 프로세스 종료 검사입니다. 이번 macOS 자체 테스트 통과에 포함하지 않습니다.

구문 검사와 실제 패키지 설치 smoke도 통과했습니다. 선별한 mutation 42개는 모두
실패하는 테스트로 탐지됐습니다. 새 목록 상한을 제거하는 오류와 모호한 테스트 쌍을
연결하는 오류도 포함하지만, 저장소 전체 mutation coverage가 100%라는 뜻은 아닙니다.
