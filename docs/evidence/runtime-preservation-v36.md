# v36 — 기존 데이터 보호 조건을 구현·복구·적용 과정에서 확인

## 이번에 고친 문제

v35의 실제 AI 후보는 원래 “새 데이터일 때만 추가”하던 관계 목록에 조건 없이
추가하는 새 메서드를 만들었습니다. 일반 테스트와 당시 독립 검사 4개는 통과했지만,
추가 JPA 검사에서 다른 소유자의 행이 옮겨지는 것을 확인했습니다. 과거 후보와 점수는
그대로 보존했습니다. 이번에는 그 후보를 직접 고치지 않고 BTH 실행 경로를 보완했습니다.

1. JVM 검증 명령 또는 Java 인접 코드가 있는 요청에만 짧은 보존 지침을 제공합니다.
2. 변경된 Java 파일의 Git 기준 코드와 후보를 비교합니다. 필드의 관계 애너테이션,
   단순 getter, 직접 컬렉션 변경문, 둘러싼 `if` 조건을 실제 구문 트리로 읽습니다.
3. 기존 조건과 맞지 않는 쓰기는 테스트 실행 전에 복구 대상으로 돌립니다. 코드 본문
   대신 파일·기준/변경 줄·소스 해시를 전달합니다. 복구에는 기존 시도 예산만 사용합니다.
4. 조건을 복원하더라도 기존 전체 필수 검증은 통과해야 합니다.
5. 과거 PASS 후보의 재사용과 자동 적용에도 같은 검사를 다시 수행합니다.

Spring JavaFormat 오류도 파일 위치가 복구 요청까지 전달되도록 했습니다. 포맷터가
줄 번호를 주지 않으면 `null`입니다. 로그에 적힌 실행 명령, 코드 본문, 임의 오류 설명은
전달하지 않습니다. 포맷터 자체를 BTH가 자동 실행하도록 추가한 것은 아닙니다.

## 무엇을 실제로 확인했나

- 보존된 v35 후보의 `Owner.java:110`이 기준 코드 `Owner.java:98`의 조건과 다름을
  3번 일관되게 찾았습니다. 후보 Git diff와 HEAD는 변하지 않았습니다.
- 같은 과제의 역사적 정답 변경에는 이 검사가 추가 보류를 만들지 않았습니다.
  정답 변경 파일에는 인식된 관계 쓰기가 없어 `not-applicable`입니다.
- 합성 Customer/Order 프로젝트에서 첫 후보 보류 → 위치를 받은 두 번째 시도 →
  조건 복원 → 필수 테스트 → 안전한 적용 흐름을 실행했습니다. **모델은 대체 실행기**입니다.
- 복구하지 않은 후보는 정해진 두 번 뒤 실패하며 적용되지 않습니다. 과거 유효한
  서명이 붙은 PASS 후보도 재사용/적용 전에 보류하며 원본·과거 기록을 변경하지 않습니다.
- 실제 v35 Maven 실패 로그의 3개 Java 포맷 오류가 복구 데이터까지 유지됩니다.
- npm tarball을 별도 임시 프로젝트에 설치하고, 설치본으로 WASM 파싱·해시 확인·
  버전 확인·설치 의존성 감사를 실행합니다. 사용자 인증 설정은 변경하지 않습니다.

최종 명령·건수·커버리지·mutation 결과는 [QA 기록](artifacts/v36/qa.json), 실제 후보와
포맷 오류·소스 해시는 [재현 결과](artifacts/v36/retained-candidate.json)에 있습니다.

## 성능과 한계

실제 후보의 Java 변경 3개를 대상으로 한 초기 WASM 측정은 약 **134–168 ms**였습니다.
Java 변경이 없는 100회 검사는 평균 **0.003 ms 미만**이며 Git/파서를 호출하지 않았습니다.
이는 이 Mac의 추가 검사 비용이고, 공유 머신의 비경합 벤치마크나 AI 구현 속도 개선값이
아닙니다. 최종 재실행 값은 위 artifact에 별도 보존합니다.

- 최대 Java 파일 32개, 파일당 UTF-8 64 KiB. 초과·비정상 경로·읽기/파싱 실패는
  `incomplete`로 보류합니다. 파서 worker는 5초 뒤 종료하며 JS heap을 128 MiB로
  제한합니다. WASM 선형 메모리·전체 프로세스 메모리 상한이나 OS 권한/네트워크
  격리를 제공하는 것은 아닙니다.
- 범위는 **필드에 관계 애너테이션이 붙은 직접 컬렉션 쓰기 구문**입니다. 별칭,
  상속, 다른 파일 호출, 반환문 속 변경, setter/property access, 호출자의 소유권,
  조건 함수 내부 동작을 증명하지 않습니다. 단순 이름 중복은 미확인으로 처리합니다.
- 조건의 구문 일치만 대조하므로 같은 의미의 조기 반환 재작성도 보류할 수 있습니다.
  별칭으로 우회한 쓰기는 놓칠 수 있다는 반례도 테스트에 명시했습니다. `clear`는
  전체 안전이 아니라 **이 좁은 검사에서 불일치를 찾지 못했다**는 뜻입니다.
- 의도적 조건 변경은 독립 리뷰를 거쳐 일반 Git 흐름으로 처리해야 합니다.
  자동 적용 우회 옵션을 추가하지 않았습니다.
- 새 실제 모델 구현·Claude 비교·회사 원본·실제 Windows·운영 DB 검증은 하지 않았습니다.
  3개 백엔드/20개 과제의 전체 구현 성공률 목표는 여전히 미완료입니다.

## 설치 검증에서 폐기한 접근

처음 시험한 `java-parser@3.0.1`의 lodash 의존성에는 공지된 취약점이 있었습니다.
로컬 override/shrinkwrap으로 감사가 통과했지만, 설치본에서는 다시 4.17.21이 들어오는
문제를 발견했습니다. 해당 의존성과 override/shrinkwrap을 제거했습니다.

최종 방식은 `web-tree-sitter@0.26.11`과 원본 그대로의 MIT Java grammar WASM입니다.
네이티브 addon·C++/Java 컴파일러·설치 hook은 쓰지 않습니다.
[출처·해시·라이선스·갱신 절차](../../vendor/tree-sitter-java/README.md).
Tree-sitter의 [공식 WASM API 문서](https://github.com/tree-sitter/tree-sitter/blob/v0.26.11/lib/binding_web/README.md)를 기준으로 구현했습니다.
